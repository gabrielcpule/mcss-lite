# MCSS-Lite components

> Every layout primitive, component and utility, with canonical examples.
> Generated from tokens/*.tokens.json and components/*.json by scripts/build.mjs. Do not edit by hand.
> Package: @gabrielpule/mcss-lite@0.3.0

## Rules

1. **Components never set their own outer margin.** Never add margin to a c-* root element. Put components inside a layout primitive (l-stack, l-cluster, l-grid, l-sidebar, l-switcher) and let it provide the spacing.
2. **Layout, then component, then utility, then token.** Solve a need with an l-* layout primitive first, then a c-* component and its modifiers, then a u-* utility. Only write custom CSS as a last resort, and then use var(--token) values only.
3. **Never invent class or token names.** Use only the classes, modifiers, elements, data-state values and tokens listed in this file. If something is missing, write custom CSS with existing tokens instead of guessing a name such as c-button--warning.
4. **States use data-state plus the native or ARIA pair.** Express component state with data-state="…" (for example data-state="error"), and always add the paired native attribute or ARIA listed for that state (disabled, aria-invalid, aria-busy).
5. **Theme with semantic tokens, never raw values.** Never hard-code colors (#hex, rgb()) or pixel spacing. Use semantic tokens (--color-text-default, --color-action-primary…) or component tokens (--button-primary-background…). Primitive color tokens (--color-gray-*, --color-blue-*) do not adapt to dark mode.

## Content rules

Labels, messages and help text follow the same rules everywhere.

- **Write in sentence case.** Capitalize only the first word and proper nouns in labels, titles, buttons and badges. Title Case is harder to scan and reads as shouting in long labels. Do: "Create account". Don't: "Create Account".
- **Buttons say what happens.** Start with a verb and name the thing it acts on. A person should know the result before they click. Do: "Save changes". Don't: "OK".
- **No vague labels.** "Submit", "Click here", "Yes" and "More" say nothing out of context. Screen reader users often hear a list of every link or button on the page, with no surrounding text. Do: "Download the invoice". Don't: "Click here".
- **Errors say what went wrong and how to fix it.** Name the problem in plain words and tell the person what to do. Don't blame, don't use codes, don't say "invalid". Do: "Enter a date after 1 January 2020". Don't: "Invalid input".
- **Show errors at the right moment.** Check a field when the person leaves it or submits the form, not while they type its first value. Once a field shows an error, clear it as soon as the value is fixed. After a failed submit, list every error at the top of the form, each linked to its field. Do: "There is a problem: Enter your email address". Don't: "Email is invalid (shown after the first keystroke)".
- **Mark optional fields, not required ones.** Ask only for what you need, then add "(optional)" to the few fields people may skip. Rows of asterisks add noise and need a legend. Do: "Phone number (optional)". Don't: "Phone number *".
- **Keep punctuation light.** No full stops on buttons, titles, labels or badges. Use full stops in help text and messages that are sentences. Avoid exclamation marks. Do: "Delete project". Don't: "Delete project!".
- **Write numbers and dates the same way everywhere.** Use numerals for numbers, the full month name in dates and a consistent time format. Avoid ambiguous dates like 03/04. Do: "1 March 2026, 12 of 20 seats". Don't: "03/01/26, twelve of twenty seats".
- **Write for everyone.** Use plain words, active voice and "you". Avoid idioms, jargon and gendered defaults. Describe what something does, not how it looks ("select", not "click the blue button"). Do: "Choose a plan to continue". Don't: "Just hit the big blue button, guys".

## Layout primitives

### Center — `l-center`

Centers a block horizontally at reading width without side gutters.

**When to use:**
- Long-form text or a single form that should sit at a comfortable reading width.

**When not to use:**
- The outermost page wrapper that also needs side gutters: use `l-container`.
- Inside another centered block: one reading width per column is enough.

**Do (example):** Center one column of reading content.

```html
<div class="l-center">
  <p class="u-margin-0">Articles read best at 60 to 75 characters per line.</p>
</div>
```

**Don't (example):** Don't nest centered blocks inside each other.

```html
<div class="l-center">
  <div class="l-center">
    <p class="u-margin-0">Twice centered.</p>
  </div>
</div>
```

**Tokens:** `--container-narrow`

**Example** (`components/layouts.html`):

```html
<section class="l-section l-section--sm">
  <div class="l-container">
    <div class="l-stack l-stack--lg">
      <h3>Projects</h3>

      <div class="l-sidebar">
        <nav class="l-sidebar__sidebar" aria-label="Filters">
          <div class="l-stack l-stack--sm">
            <a href="#all">All</a>
            <a href="#mine">Mine</a>
          </div>
        </nav>
        <div class="l-sidebar__content">
          <div class="l-grid l-grid--3-col">
            <div class="c-card">One</div>
            <div class="c-card">Two</div>
            <div class="c-card">Three</div>
          </div>
        </div>
      </div>

      <div class="l-switcher" style="--switcher-threshold: 40rem">
        <div class="c-card">Side by side on wide screens</div>
        <div class="c-card">Stacked on narrow screens</div>
      </div>

      <div class="l-center">
        <p class="u-text-center">Centered at reading width.</p>
      </div>
    </div>
  </div>
</section>
```

### Cluster — `l-cluster`

Horizontal group that wraps, with a gap and vertically centered items: button groups, badge lists, tags.

**When to use:**
- Button groups, badge lists, tags and metadata rows that should wrap on narrow screens.

**When not to use:**
- Two columns of page content: use `l-sidebar` or `l-grid`.
- Items that must stay equal width: use `l-switcher`.

**Do:**
- Group inline items such as buttons and badges.

**Don't:**
- Using l-cluster for two-column page layouts; use l-sidebar or l-grid.

**Do (example):** Let items wrap; the gap holds on every row.

```html
<div class="l-cluster">
  <span class="c-badge">Design</span>
  <span class="c-badge">Research</span>
  <span class="c-badge">Accessibility</span>
</div>
```

**Don't (example):** Don't space items with margins. (`mcss-lite validate` reports `[golden-rule]`)

```html
<div class="l-cluster">
  <button type="button" class="c-button" style="margin-right: 8px">Back</button>
  <button type="button" class="c-button c-button--primary">Next</button>
</div>
```

**Tokens:** `--space-3`

**Example** (`components/layouts.html`):

```html
<section class="l-section l-section--sm">
  <div class="l-container">
    <div class="l-stack l-stack--lg">
      <h3>Projects</h3>
```

### Container — `l-container`

Centers page content horizontally with a max width and side gutters.

**When to use:**
- The outermost wrapper of each page region: header, main content, footer.

**When not to use:**
- Narrowing text inside a region: use `l-center`.
- Inside another container.

**Modifiers — width** (pick at most one):
- `l-container--narrow`: Reading width (48rem) for articles and forms.

**Do:**
- Use once per page region, as the outermost wrapper of the content.

**Don't:**
- Nesting containers.

**Do (example):** Use one container per region.

```html
<header>
  <div class="l-container">
    <p class="u-margin-0">Acme</p>
  </div>
</header>
```

**Don't (example):** Don't invent width modifiers. (`mcss-lite validate` reports `[unknown-class]`)

```html
<div class="l-container l-container--wide">
  <p class="u-margin-0">Acme</p>
</div>
```

**Tokens:** `--container-max-width`, `--container-narrow`, `--space-4`

### Grid — `l-grid`

Two-dimensional grid with a fixed gap. Column modifiers collapse to one column below 768px.

**When to use:**
- Card collections of unknown length: l-grid--responsive fits as many columns as there is room for.
- Dashboards with a fixed number of equal columns: l-grid--2-col, --3-col or --4-col.

**When not to use:**
- A main area with a narrower side column: use `l-sidebar`.
- A row of equal items that should all stack at once: use `l-switcher`.

**Modifiers — columns** (pick at most one):
- `l-grid--2-col`: Two equal columns.
- `l-grid--3-col`: Three equal columns.
- `l-grid--4-col`: Four equal columns.
- `l-grid--responsive`: As many 280px-minimum columns as fit; no breakpoint needed.

**Do:**
- Prefer l-grid--responsive for card collections of unknown length.

**Don't:**
- Adding margins to grid children; the gap already spaces them.

**Do (example):** Keep the source order the same as the visual order.

```html
<div class="l-grid l-grid--3-col">
  <section class="c-card"><p class="u-margin-0">Step 1</p></section>
  <section class="c-card"><p class="u-margin-0">Step 2</p></section>
  <section class="c-card"><p class="u-margin-0">Step 3</p></section>
</div>
```

**Don't (example):** Don't combine column modifiers. (`mcss-lite validate` reports `[exclusive-modifiers]`)

```html
<div class="l-grid l-grid--2-col l-grid--responsive">
  <section class="c-card"><p class="u-margin-0">Step 1</p></section>
</div>
```

**Content:**
- If you reorder items visually with CSS, keyboard and screen reader users still get the source order, so change the markup instead.

**Tokens:** `--space-6`

**Example** (`components/layouts.html`):

```html
<section class="l-section l-section--sm">

          </div>
        </div>
```

### Section — `l-section`

Vertical padding for a full-width page section.

**When to use:**
- Full-width bands of a page that need vertical breathing room, such as a hero or a feature row.

**When not to use:**
- Spacing between components inside a section: use `l-stack`.
- A bordered group of content: use `c-card`.

**Modifiers — size** (pick at most one):
- `l-section--sm`: Smaller vertical padding (2.5rem instead of 4rem).

**Structure:**
- Usually contains one l-container.

**Do (example):** Put a container inside the section for the side gutters.

```html
<section class="l-section">
  <div class="l-container">
    <h2 class="u-margin-0">Features</h2>
  </div>
</section>
```

**Don't (example):** Don't invent size modifiers; use l-section--sm for a tighter band. (`mcss-lite validate` reports `[unknown-class]`)

```html
<section class="l-section l-section--xl">

</section>
```

### Sidebar — `l-sidebar`

A sidebar next to main content that stacks when the content would get narrower than 50%.

**When to use:**
- Filters next to results, a form label next to its field, an avatar next to text.
- Any side column that should drop below the content when space runs out.

**When not to use:**
- Equal columns: use `l-grid` or `l-switcher`.
- Page-level navigation that must stay fixed while scrolling: that is app chrome, outside this layout.

**Elements:**
- `l-sidebar__sidebar` (required): The narrow side (16rem basis).
- `l-sidebar__content` (required): The main content; takes the remaining space.

**Structure:**
- Exactly two children: l-sidebar__sidebar and l-sidebar__content, in either order.

**Do (example):** Put the side column first in the source only if it should also be read first.

```html
<div class="l-sidebar">
  <aside class="l-sidebar__sidebar"><p class="u-margin-0">Filters</p></aside>
  <div class="l-sidebar__content"><p class="u-margin-0">42 results</p></div>
</div>
```

**Don't (example):** Don't use the sidebar elements on their own. (`mcss-lite validate` reports `[element-outside-block]`)

```html
<aside class="l-sidebar__sidebar"><p class="u-margin-0">Filters</p></aside>
```

**Tokens:** `--space-6`

**Example** (`components/layouts.html`):

```html
<section class="l-section l-section--sm">
  <div class="l-container">
    <div class="l-stack l-stack--lg">
      <h3>Projects</h3>

      <div class="l-sidebar">

        <div class="l-sidebar__content">

          </div>
        </div>

        <div class="c-card">Side by side on wide screens</div>

        <p class="u-text-center">Centered at reading width.</p>

  </div>
</section>
```

### Stack — `l-stack`

Vertical flow: adds space between consecutive children, which keep their own width. Bare inline children (links, spans) stack too. The default way to space components vertically.

**When to use:**
- Anything that flows top to bottom: form fields, paragraphs, a card body, a page column.
- Changing rhythm: nest a smaller stack (l-stack--sm) inside a larger one.

**When not to use:**
- Items in a row that wrap: use `l-cluster`.
- Two-dimensional layouts: use `l-grid`.

**Modifiers — gap** (pick at most one):
- `l-stack--sm`: Tight spacing (0.5rem), e.g. form-field internals or list items.
- `l-stack--lg`: Loose spacing (2rem), e.g. between page blocks.

**Do:**
- Nest stacks with different gaps to build rhythm.

**Don't:**
- Adding margins to children to fix spacing; change the stack modifier instead.

**Do (example):** Let the stack own the space between its children.

```html
<div class="l-stack">
  <h2 class="u-margin-0">Billing</h2>
  <p class="u-margin-0">Your plan renews on 1 March.</p>
  <div class="l-cluster">
    <button type="button" class="c-button">Change plan</button>
  </div>
</div>
```

**Don't (example):** Don't fix spacing with margins on the children. (`mcss-lite validate` reports `[golden-rule]`)

```html
<div class="l-stack">
  <section class="c-card" style="margin-top: 32px"><p class="u-margin-0">Plan</p></section>
</div>
```

**Do (example):** Pick the gap with a modifier.

```html
<div class="l-stack l-stack--sm">
  <p class="u-margin-0">Line one</p>
  <p class="u-margin-0">Line two</p>
</div>
```

**Don't (example):** Don't combine two gap modifiers. (`mcss-lite validate` reports `[exclusive-modifiers]`)

```html
<div class="l-stack l-stack--sm l-stack--lg">
```

### Switcher — `l-switcher`

Children sit side by side until the container is narrower than a threshold, then all stack at once.

**When to use:**
- Two to four items of equal importance, such as pricing tiers or steps, that should switch from a row to a column all at once.

**When not to use:**
- Items of unequal importance: use `l-sidebar`.
- Five or more items, or a list of unknown length: use `l-grid` with l-grid--responsive.

**Custom properties:**
- `--switcher-threshold` (default `30rem`): Container width below which children stack. Set inline, e.g. style="--switcher-threshold: 40rem".

**Do (example):** Set the threshold with the custom property.

```html
<div class="l-switcher" style="--switcher-threshold: 40rem">
  <section class="c-card"><p class="u-margin-0">Free</p></section>
  <section class="c-card"><p class="u-margin-0">Team</p></section>
</div>
```

**Don't (example):** Don't invent size modifiers. (`mcss-lite validate` reports `[unknown-class]`)

```html
<div class="l-switcher l-switcher--wide">
  <section class="c-card"><p class="u-margin-0">Free</p></section>
</div>
```

**Tokens:** `--space-4`

## Components

### Badge — `c-badge`

A short, non-interactive label for status or category, such as "Beta" or "Paid".

**When to use:**
- Showing the status of an item: Draft, Active, Failed.
- A short category or plan label: Beta, Pro.

**When not to use:**
- Anything clickable, removable or filterable: use `c-button` with c-button--sm.
- A count on a navigation item: badges here are for status words, not numbers.
- A sentence: use body text or an alert.

**Apply to:** `<span>`

**Modifiers — tone** (pick at most one):
- `c-badge--primary`: Brand emphasis, e.g. "New".
- `c-badge--success`: Positive status, e.g. "Active".
- `c-badge--warning`: Needs attention, e.g. "Expiring".
- `c-badge--error`: Negative status, e.g. "Failed".
- `c-badge--info`: Neutral information, e.g. "Draft".

**Do:**
- Keep badge text to one or two words.
- Group several badges with l-cluster.

**Don't:**
- Making a badge clickable; use c-button--sm instead.
- Relying on badge color alone to convey meaning; the text must carry the status.

**Do (example):** Say the status in words; the tone only supports it.

```html
<div class="l-cluster">
  <span class="c-badge c-badge--error">Failed</span>
  <span class="c-badge c-badge--success">Passed</span>
</div>
```

**Don't (example):** Don't make a badge clickable or invent tones. (`mcss-lite validate` reports `[unknown-class]`)

```html
<span class="c-badge c-badge--danger">Failed</span>
```

**Content:**
- One or two words, sentence case: "In review", not "IN REVIEW".
- Each tone keeps one meaning across the product: error always means something failed.

**Accessibility:**
- Color is decorative; the badge text must describe the status on its own.

**Tokens:** `--badge-background`, `--badge-text`, `--color-action-primary`, `--color-text-on-action`

**Example** (`components/badge.html`):

```html
<div class="l-cluster">
  <span class="c-badge">Draft</span>
  <span class="c-badge c-badge--primary">New</span>
  <span class="c-badge c-badge--success">Active</span>
  <span class="c-badge c-badge--warning">Expiring</span>
  <span class="c-badge c-badge--error">Failed</span>
  <span class="c-badge c-badge--info">Beta</span>
</div>
```

### Button — `c-button`

Triggers an action. Apply to <button>. Apply to <a> only when the control navigates. Parts have a 2px keyline and a brick edge that drops when pressed.

**When to use:**
- The control does something on this page: submits a form, saves, deletes, opens a dialog, toggles a setting.
- A confirming or cancelling action in a form or `c-modal` footer.
- An on/off toolbar control such as Bold or Mute, with aria-pressed.

**When not to use:**
- The control goes to another page or URL: use a plain link. Apply c-button to an <a> only when a link must look like a button, such as a start-page call to action.
- Showing a status that does nothing when clicked: use `c-badge`.
- Filtering or removing items in a list of tags: that is a chip, which MCSS-Lite does not ship yet.

**Apply to:** `<button>`, `<a>`

**Modifiers — variant** (pick at most one):
- `c-button--primary`: The main action in a view region. Use at most one per region.
- `c-button--secondary`: Outlined in the action color; for important but not main actions.
- `c-button--ghost`: No border or background; for low-emphasis actions such as Cancel.
- `c-button--danger`: Destructive, hard-to-undo actions such as Delete. Brick red.

**Modifiers — size** (pick at most one):
- `c-button--sm`: Compact button for dense UI such as tables and toolbars.
- `c-button--lg`: Large button for hero or empty-state calls to action.

**States:**
- `data-state="disabled"`: The action cannot run right now. Rendered ghosted with a dashed keyline. Prefer aria-disabled="true": the button stays focusable, so link a visible reason with aria-describedby and ignore activation in your handler. The disabled attribute also works on <button> but removes it from the tab order. On <a>, set aria-disabled="true" and remove href.
- `data-state="loading"`: The action is in progress. Shows moving stripes; text keeps full contrast. Set aria-busy="true" and aria-disabled="true", keep the visible label (for example "Saving…"), and ignore activation in your handler.

**Do:**
- Group buttons with l-cluster; it provides the gap.
- Order a button group as secondary or ghost actions first, then the primary action last.
- Write labels as verbs that name the outcome: "Save changes", not "OK".
- For toggle buttons (for example a theme switch), set aria-pressed="true" on the selected one; it gets the pressed style automatically.
- Use c-button--danger for the confirming action of anything destructive, never c-button--primary.

**Don't:**
- Adding margin to .c-button. Spacing belongs to the layout parent.
- Combining two variant modifiers (for example c-button--primary c-button--ghost).
- Using c-button on a <div> or <span>.

**Do (example):** Use one primary button per region, placed last in its group.

```html
<div class="l-cluster">
  <button type="button" class="c-button c-button--ghost">Cancel</button>
  <button type="submit" class="c-button c-button--primary">Save changes</button>
</div>
```

**Don't (example):** Don't combine two variants on one button to make it stand out more. (`mcss-lite validate` reports `[exclusive-modifiers]`)

```html
<button type="submit" class="c-button c-button--primary c-button--danger">Save changes</button>
```

**Do (example):** Keep an unavailable action focusable and say why it can't run, with aria-disabled and a linked reason.

```html
<div class="l-stack l-stack--sm">
  <button type="button" class="c-button c-button--primary" data-state="disabled" aria-disabled="true" aria-describedby="publish-why">Publish</button>
  <p id="publish-why" class="u-margin-0">Add a title before you publish.</p>
</div>
```

**Don't (example):** Don't grey out a button without saying why, or set the state without its native pair. (`mcss-lite validate` reports `[state-pair]`)

```html
<button type="button" class="c-button" data-state="disabled">Publish</button>
```

**Do (example):** Invent nothing: a warning-style action is c-button--danger or a plain button.

```html
<button type="button" class="c-button c-button--danger">Delete project</button>
```

**Don't (example):** Don't guess a modifier that isn't in the contract. (`mcss-lite validate` reports `[unknown-class]`)

```html
<button type="button" class="c-button c-button--warning">Delete project</button>
```

**Content:**
- Write a verb plus the thing it acts on: "Save changes", "Delete project". Never "OK", "Submit" or "Click here".
- Use sentence case: "Create account", not "Create Account".
- Keep the label the same when a toggle changes state; aria-pressed carries the state.
- A danger button names what is destroyed: "Delete account", not "Confirm".
- No full stop at the end of a label.

**Accessibility:**
- A button needs a visible text label, or aria-label when it only contains an icon.
- Do not remove the :focus-visible outline.
- Use type="button" unless the button submits a form.
- c-button--sm looks compact but keeps a 44px tall hit area.
- Don't disable a submit button until the form is valid. Let people submit, then show what is missing.

**Keyboard:**
- Enter: Activates the button.
- Space: Activates the button (not links).
- Tab: Moves focus to the button, including one marked aria-disabled.

**Tokens:** `--button-background`, `--button-background-hover`, `--button-border`, `--button-text`, `--button-radius`, `--button-shadow`, `--button-primary-background`, `--button-primary-background-hover`, `--button-primary-text`, `--button-secondary-text`, `--button-secondary-border`, `--button-ghost-background-hover`, `--button-danger-background`, `--button-danger-background-hover`, `--button-danger-text`, `--button-pressed-background`, `--button-pressed-border`, `--button-pressed-text`, `--button-primary-border`, `--button-danger-border`, `--button-primary-background-active`

**Example** (`components/button.html`):

```html
<div class="l-cluster">
  <button type="button" class="c-button c-button--ghost">Cancel</button>
  <button type="button" class="c-button">Save draft</button>
  <button type="button" class="c-button c-button--primary">Publish</button>
</div>

<div class="l-cluster">
  <button type="button" class="c-button c-button--secondary c-button--sm">Export</button>
  <a class="c-button c-button--secondary" href="/docs">Read the docs</a>
  <button type="button" class="c-button c-button--primary c-button--lg">Start free trial</button>
</div>

<div class="l-cluster">
  <button type="button" class="c-button" data-state="disabled" disabled>Unavailable</button>
  <button type="button" class="c-button c-button--primary" data-state="loading" aria-busy="true" aria-disabled="true">Saving…</button>
</div>

<div class="l-cluster" role="group" aria-label="Theme">
  <button type="button" class="c-button c-button--sm" aria-pressed="true">Light</button>
  <button type="button" class="c-button c-button--sm" aria-pressed="false">Dark</button>
</div>

<button type="button" class="c-button c-button--danger">Delete project</button>
```

### Card — `c-card`

A raised surface that groups related content, such as a summary, a settings group or a list item.

**When to use:**
- A collection of similar items people browse and open one at a time: projects, articles, plans.
- A dashboard summary that groups a figure with its actions.
- A group of related settings.

**When not to use:**
- People compare items side by side or scan dense data: use a list or table.
- Grouping inside another card: use `l-stack` and a heading instead of a card in a card.
- A page section with no border of its own: use `l-section`.

**Apply to:** `<article>`, `<section>`, `<div>`, `<li>`, `<a>`

**Modifiers — surface** (pick at most one):
- `c-card--elevated`: Stronger shadow to lift the card above its neighbors.
- `c-card--bordered`: Keyline only, no brick edge; for flat, dense layouts.

**Modifiers — behavior** (combinable):
- `c-card--interactive`: The whole card is clickable; shows hover feedback.

**Elements:**
- `c-card__header`: Top area; holds the title and optional badges. On `<header>`/`<div>`.
- `c-card__title`: Card heading. Use the heading level that fits the page outline. On `<h2>`/`<h3>`/`<h4>`/`<h5>`/`<h6>`.
- `c-card__body`: Main content. On `<div>`/`<p>`.
- `c-card__footer`: Bottom area for actions or metadata; has a top divider. On `<footer>`/`<div>`.

**Structure:**
- Elements appear in the order header, body, footer. All are optional.
- c-card__title goes inside c-card__header.

**Do:**
- Place cards in l-grid or l-stack; the layout sets the gap between cards.
- For c-card--interactive, make the card an <a> or put one link inside whose area covers the card.

**Don't:**
- Nesting cards inside cards.
- Adding margin to .c-card.
- Putting several competing links inside a c-card--interactive.

**Do (example):** Put the link on the title and add c-card--interactive; the link covers the card and other actions stay clickable.

```html
<article class="c-card c-card--interactive">
  <div class="c-card__header">
    <h3 class="c-card__title"><a href="#atlas">Atlas</a></h3>
  </div>
  <div class="c-card__body">
    <p class="u-margin-0">Updated 2 hours ago</p>
  </div>
</article>
```

**Don't (example):** Don't wrap the whole card in a link: screen readers read the entire card as one long link name. (`mcss-lite validate` reports `[card-link]`)

```html
<a class="c-card c-card--interactive" href="#atlas">
  <h3 class="c-card__title">Atlas</h3>
  <p class="u-margin-0">Updated 2 hours ago</p>
</a>
```

**Do (example):** Let the grid space the cards.

```html
<div class="l-grid l-grid--responsive">
  <section class="c-card c-card--bordered"><p class="u-margin-0">Storage: 4 GB of 10 GB</p></section>
  <section class="c-card c-card--bordered"><p class="u-margin-0">Seats: 12 of 20</p></section>
</div>
```

**Don't (example):** Don't space cards with their own margin. (`mcss-lite validate` reports `[golden-rule]`)

```html
<section class="c-card" style="margin-block-end: 16px"><p class="u-margin-0">Storage: 4 GB of 10 GB</p></section>
```

**Content:**
- The title names the thing, not the action: "Atlas", not "View Atlas".
- Keep the body to one or two lines of summary; details belong on the page the card opens.

**Accessibility:**
- An interactive card must be reachable with the keyboard: use a real <a> or <button>, never a click handler on a <div>.
- Keep the title a real heading so screen reader users can navigate by headings.

**Keyboard:**
- Tab: Focuses the title link (the card shows the focus ring), then any other actions in the card.

**Tokens:** `--card-background`, `--card-border`, `--card-border-hover`, `--card-radius`, `--card-padding`, `--card-shadow`, `--card-shadow-elevated`

**Example** (`components/card.html`):

```html
<div class="l-grid l-grid--responsive">
  <article class="c-card">
    <header class="c-card__header">
      <div class="l-cluster">
        <h3 class="c-card__title">Team plan</h3>
        <span class="c-badge c-badge--success">Active</span>
      </div>
    </header>
    <div class="c-card__body">
      <p class="u-margin-0">12 of 20 seats used. Renews on 1 March.</p>
    </div>
    <footer class="c-card__footer">
      <div class="l-cluster">
        <button type="button" class="c-button c-button--sm">Manage seats</button>
      </div>
    </footer>
  </article>

  <article class="c-card c-card--interactive">
    <div class="c-card__header">
      <h3 class="c-card__title"><a href="/projects/atlas">Atlas</a></h3>
    </div>
    <div class="c-card__body">
      <p class="u-margin-0">Updated 2 hours ago</p>
    </div>
  </article>

  <section class="c-card c-card--bordered">
    <div class="c-card__body">
      <p class="u-margin-0">Bordered cards suit dense, flat layouts.</p>
    </div>
  </section>
</div>
```

### Form field — `c-form-field`

Wraps one form control with its label, help text and error message.

**When to use:**
- Any form control that needs a label, help text or an error message.
- Each field of a form; stack the fields with `l-stack`.

**When not to use:**
- A search box in a toolbar with a visible button: a labelled `c-input` inside `l-cluster` is enough, with a visually hidden label.

**Apply to:** `<div>`, `<fieldset>`

**Elements:**
- `c-form-field__label` (required): The field label. On `<label>`/`<legend>`.
- `c-form-field__help`: Hint shown below the control. On `<p>`/`<div>`/`<span>`.
- `c-form-field__error`: Error message shown when the control has data-state="error". On `<p>`/`<div>`/`<span>`.

**Structure:**
- Order: c-form-field__label, then the control (c-input), then c-form-field__help and/or c-form-field__error.

**Do:**
- Stack several c-form-field blocks with l-stack.

**Don't:**
- Adding margin to .c-form-field; the layout parent spaces fields.

**Do (example):** Link help and error text to the control with aria-describedby.

```html
<div class="c-form-field">
  <label class="c-form-field__label" for="phone">Phone number (optional)</label>
  <p class="c-form-field__help" id="phone-help">For delivery updates only.</p>
  <input class="c-input" id="phone" type="tel" autocomplete="tel" aria-describedby="phone-help">
</div>
```

**Don't (example):** Don't use the elements outside their block: the help text loses its spacing and link. (`mcss-lite validate` reports `[element-outside-block]`)

```html
<p class="c-form-field__help">For delivery updates only.</p>
```

**Do (example):** Space fields with l-stack.

```html
<form class="l-stack">
  <div class="c-form-field">
    <label class="c-form-field__label" for="first">First name</label>
    <input class="c-input" id="first" autocomplete="given-name">
  </div>
  <div class="c-form-field">
    <label class="c-form-field__label" for="last">Last name</label>
    <input class="c-input" id="last" autocomplete="family-name">
  </div>
</form>
```

**Don't (example):** Don't push fields apart with margins on the field. (`mcss-lite validate` reports `[golden-rule]`)

```html
<div class="c-form-field" style="margin-bottom: 24px">
  <label class="c-form-field__label" for="first2">First name</label>
  <input class="c-input" id="first2">
</div>
```

**Content:**
- Labels are short nouns in sentence case: "Email address", not "Please Enter Your Email".
- Help text explains format or why you ask; keep it to one sentence.
- Mark optional fields "(optional)" and ask only for what you need.
- After a failed submit, list every error at the top of the form, each linked to its field.

**Accessibility:**
- Connect label and control with for/id.
- Give help and error elements ids and list them in the control's aria-describedby.
- Use role="alert" or a live region on the error when it appears after submit.

**Tokens:** `--color-text-muted`, `--color-text-subtle`, `--color-text-error`

**Example** (`components/form-field.html`):

```html
<form class="l-stack" novalidate>
  <div class="c-form-field">
    <label class="c-form-field__label" for="email">Work email</label>
    <input class="c-input" id="email" type="email" autocomplete="email" aria-describedby="email-help">
    <p class="c-form-field__help" id="email-help">We'll send the invite here.</p>
  </div>

  <div class="c-form-field">
    <label class="c-form-field__label" for="password">Password</label>
    <input class="c-input" id="password" type="password" data-state="error" aria-invalid="true" aria-describedby="password-error">
    <p class="c-form-field__error" id="password-error">Use at least 12 characters.</p>
  </div>

  <div class="c-form-field">
    <label class="c-form-field__label" for="org">Organization</label>
    <input class="c-input" id="org" type="text" value="Acme Inc." data-state="disabled" disabled>
  </div>

  <div class="l-cluster">
    <button type="submit" class="c-button c-button--primary">Create account</button>
  </div>
</form>
```

### Input — `c-input`

Single-line text entry. Also styles <textarea> and <select>.

**When to use:**
- One line of free text: a name, an email address, a search query, a number.
- Multi-line text on a <textarea>, or a choice from many options on a <select>.

**When not to use:**
- Choosing among 2 to 6 visible options: radio buttons read faster than a select (coming in 0.4.0).
- A yes/no setting: a checkbox (coming in 0.4.0).
- Showing a value that cannot change: plain text, not a read-only input.

**Apply to:** `<input>`, `<textarea>`, `<select>`

**States:**
- `data-state="error"`: The value is invalid. Adds a heavier bottom edge so the state does not rely on color. Set aria-invalid="true" and aria-describedby pointing at the c-form-field__error message.
- `data-state="success"`: The value was validated successfully.
- `data-state="disabled"`: The field cannot be edited. Rendered ghosted with a dashed keyline. Also set the disabled attribute.

**Do:**
- Always wrap in c-form-field with a c-form-field__label.
- Use the right type attribute (email, tel, number, search) so mobile keyboards match.

**Don't:**
- Using placeholder text as the only label.
- Setting a width on .c-input; it fills its container. Constrain the container instead.

**Do (example):** Give every input a visible label that stays visible while typing.

```html
<div class="c-form-field">
  <label class="c-form-field__label" for="email">Email address</label>
  <input class="c-input" id="email" type="email" autocomplete="email">
</div>
```

**Don't (example):** Don't use the placeholder as the label: it disappears as soon as someone types.

```html
<input class="c-input" type="email" placeholder="Email address">
```

**Do (example):** Pair the error state with aria-invalid and link the message with aria-describedby.

```html
<div class="c-form-field">
  <label class="c-form-field__label" for="start">Start date</label>
  <input class="c-input" id="start" data-state="error" aria-invalid="true" aria-describedby="start-error">
  <p class="c-form-field__error" id="start-error">Enter a start date after 1 January 2020.</p>
</div>
```

**Don't (example):** Don't show an error with a red border alone. (`mcss-lite validate` reports `[state-pair]`)

```html
<input class="c-input" data-state="error">
```

**Content:**
- Error messages say what went wrong and how to fix it: "Enter a date after 1 January 2020", not "Invalid date".
- Show errors when the person leaves the field or submits, not while they type the first value. Once a field is in error, clear the message as soon as it is fixed.
- Mark the few optional fields with "(optional)" in the label; don't add asterisks to required ones.

**Accessibility:**
- Every input needs a programmatic label: <label for> on c-form-field__label.
- Error text must be linked with aria-describedby, not only shown in red.

**Keyboard:**
- Tab: Moves focus into and out of the field.

**Tokens:** `--input-background`, `--input-border`, `--input-border-focus`, `--input-text`, `--input-placeholder`, `--input-radius`, `--color-focus-ring`, `--color-focus-ring-error`

**Example** (`components/input.html`):

```html
<div class="c-form-field">
  <label class="c-form-field__label" for="search">Search projects</label>
  <input class="c-input" id="search" type="search" placeholder="Name or ID">
</div>
```

```html
  <label class="c-form-field__label" for="name">Name</label>
  <input class="c-input" id="name">

```

### Modal — `c-modal`

A dialog over the page that blocks interaction until dismissed. Works on <dialog> (preferred, opened with showModal()) or on a <div role="dialog">.

**When to use:**
- Confirming a destructive or irreversible action, such as deleting a project.
- A short task that must not lose the page behind it, such as renaming an item.
- Warning that unsaved work will be lost.

**When not to use:**
- Long or scrolling content, or anything with its own navigation: make it a page.
- Success messages and tips: show them inline on the page.
- Opening a dialog from a dialog: keep it to one level where you can, two at most.

**Apply to:** `<dialog>`, `<div>`

**Elements:**
- `c-modal__backdrop`: Dimmed layer behind the dialog; clicking it may close the modal. On `<div>`.
- `c-modal__container` (required): The dialog panel. On `<div>`/`<form>`.
- `c-modal__header`: Holds the title and close button. On `<header>`/`<div>`.
- `c-modal__title` (required): Dialog heading, referenced by aria-labelledby. On `<h2>`/`<h3>`.
- `c-modal__close`: Icon button that closes the dialog. On `<button>`.
- `c-modal__body`: Dialog content. On `<div>`.
- `c-modal__footer`: Actions, right-aligned. Put the primary action last. On `<footer>`/`<div>`.

**States:**
- `data-state="closed"`: Hidden (div form). With <dialog>, use the open attribute / showModal() instead. When closed, return focus to the control that opened the modal.

**Structure:**
- c-modal contains c-modal__backdrop and c-modal__container as siblings.
- c-modal__container contains header, body and footer in that order.

**Do:**
- Use for short, focused tasks: confirmations, small forms.
- Buttons in c-modal__footer are c-button; the footer provides the gap. Use c-button--danger for destructive confirmations.

**Don't:**
- Opening a modal from another modal.
- Long, scrolling content; use a page instead.

**Do (example):** Use <dialog> opened with showModal(), named by its title, with verb buttons.

```html
<dialog class="c-modal" aria-labelledby="leave-title">
  <div class="c-modal__container">
    <div class="c-modal__header">
      <h2 class="c-modal__title" id="leave-title">Discard your changes?</h2>
    </div>
    <div class="c-modal__footer">
      <div class="l-cluster">
        <button type="button" class="c-button c-button--ghost">Keep editing</button>
        <button type="button" class="c-button c-button--danger">Discard changes</button>
      </div>
    </div>
  </div>
</dialog>
```

**Don't (example):** Don't build a dialog from a bare <div>: no focus handling, no Escape, nothing announced. (`mcss-lite validate` reports `[a11y]`)

```html
<div class="c-modal">
  <div class="c-modal__container">Discard your changes?</div>
</div>
```

**Do (example):** Label the close button.

```html
<dialog class="c-modal" aria-labelledby="share-title">
  <div class="c-modal__container">
    <div class="c-modal__header">
      <h2 class="c-modal__title" id="share-title">Share project</h2>
      <button type="button" class="c-modal__close" aria-label="Close"><svg viewBox="0 0 16 16" aria-hidden="true" focusable="false"><path d="M4 4l8 8M12 4l-8 8" fill="none" stroke="currentColor" stroke-width="2"/></svg></button>
    </div>
  </div>
</dialog>
```

**Don't (example):** Don't leave an icon-only close button without a name. (`mcss-lite validate` reports `[a11y]`)

```html
<dialog class="c-modal" aria-labelledby="share-title2">
  <div class="c-modal__container">
    <h2 class="c-modal__title" id="share-title2">Share project</h2>
    <button type="button" class="c-modal__close">×</button>
  </div>
</dialog>
```

**Content:**
- Title the dialog with the question or task: "Delete this project?"
- Button labels repeat the verb: "Delete project" and "Keep project", never "OK" and "Cancel".
- Say what happens next in one or two sentences in the body.

**Accessibility:**
- Prefer <dialog class="c-modal"> opened with showModal(): the browser then handles focus, Escape and inertness. With a <div>, set role="dialog", aria-modal="true" and manage focus yourself.
- Reference the title with aria-labelledby.
- With the <div> form, make the page behind inert and lock scrolling while open, trap focus, close on Escape, and return focus to the opener.
- c-modal__close needs aria-label="Close" and an SVG icon, not a text glyph.

**Keyboard:**
- Escape: Closes the dialog and returns focus to the control that opened it.
- Tab: Moves focus between controls inside the dialog only.

**Tokens:** `--modal-background`, `--modal-backdrop`, `--modal-border`, `--modal-radius`, `--modal-shadow`, `--z-index-modal`, `--z-index-modal-backdrop`

**Example** (`components/modal.html`):

```html
<div class="c-modal" role="dialog" aria-modal="true" aria-labelledby="delete-title">
  <div class="c-modal__backdrop"></div>
  <div class="c-modal__container">
    <header class="c-modal__header">
      <h2 class="c-modal__title" id="delete-title">Delete project?</h2>
      <button type="button" class="c-modal__close" aria-label="Close"><svg viewBox="0 0 20 20" aria-hidden="true" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round"><path d="M5 5l10 10M15 5L5 15"/></svg></button>
    </header>
    <div class="c-modal__body">
      <p class="u-margin-0">Atlas and its 42 files will be deleted. This can't be undone.</p>
    </div>
    <footer class="c-modal__footer">
      <button type="button" class="c-button c-button--ghost">Keep project</button>
      <button type="button" class="c-button c-button--danger">Delete project</button>
    </footer>
  </div>
</div>
```

## Utilities

Single-purpose overrides with !important. Use sparingly; reach for a layout or component first.

- `u-text-center`: Center-align text.
- `u-text-left`: Align text to the start (left in left-to-right languages).
- `u-text-right`: Align text to the end (right in left-to-right languages).
- `u-hidden`: display: none.
- `u-visible`: visibility: visible.
- `u-invisible`: visibility: hidden; keeps the space.
- `u-margin-0`: Remove margin, e.g. from a heading or paragraph inside a component.
- `u-padding-0`: Remove padding.
- `u-font-normal`: Normal font weight.
- `u-font-medium`: Medium font weight.
- `u-font-semibold`: Semibold font weight.
- `u-font-bold`: Bold font weight.
- `u-font-mono`: Monospace font.
- `u-truncate`: Single line with an ellipsis.
- `u-sr-only`: Visually hidden but read by screen readers.
